Notation: E = straightforward once specified; M = standard intermediate reasoning; H = greater modeling or implementation risk. Complexity excludes input/output storage unless noted, and uses unit-cost arithmetic unless explicitly qualified. Hash-based bounds are expected bounds, not worst-case guarantees.

## Resulting priorities

1. **Parsing, formatting, and exact specifications.** Delimited records, whole lines, blank-line case boundaries, CSV arrays, and mixed formats recur throughout all four papers. This deserves six opening pages of paired C++17/Python examples.
2. **Arrays, strings, counting, sorting, and intervals.** CPU and laptop Rentals are a particularly strong repeated archetype. Frequency tables, deterministic tie-breaking, minimum covering windows, interval merging, and monotonic stacks have direct evidence.
3. **Graph modeling and connectivity.** MST savings, travel-time paths, dependencies, airport reachability, bridges, multi-source propagation, and explicit A* path reconstruction require more than just BFS and DFS.
4. **DP with an explicit state and arithmetic policy.** Knapsack, edit distance, palindrome cuts, stock trading, interval measurements, Catalan counts, and grid path counts are evidenced. Correct state definitions and loop order are more valuable here than a long list of formulas.
5. **Bounded search, simulation, and arithmetic observations.** IP address splits, Sudoku, BST construction, waterfall propagation, rectangle counting, tiered arithmetic, and circular fuel balance merit worked examples.
6. **Compact foundations.** Binary search, prefix sums, difference arrays, basic number theory, XOR, ordinary coin change, LIS, and bipartiteness are transferable foundations; their inclusion must not be described as repeated historical evidence.

The set spans basic implementation through substantial intermediate algorithms. The 2022 paper has many small parsing/simulation tasks but also knapsack, MST, and shortest-path modeling. The 2023 paper emphasizes sorting, DP, dependencies, and simulation. The 2024 and 2025 papers include SCC reasoning, monotonic stacks, state-space memoization, bridges, and Sudoku. This is evidence for a mixed toolkit, not proof of a monotonic increase in official contest difficulty.

## Inclusion boundaries

**Historically evidenced:** custom parsing/formatting, frequency tables, sorting/comparators, interval resource allocation and merging, inversion counting, balanced-parentheses scans, monotonic stacks, minimum covering window, bounded string matching, backtracking, BST modeling, BFS/grid propagation, weighted paths, MST/DSU, topological ordering, SCC condensation, bridges, A*, knapsack, edit distance, palindrome partitioning, stock DP, residual-range memoization, Catalan/grid counts, elementary geometry and simulation.

**Foundational:** complexity/overflow, prefix sums/frequencies, difference arrays, binary search on answer, general two pointers, Kadane, subsets/permutations/XOR, bipartite testing, simple tree properties, coin change, LIS, GCD/LCM, sieve/factorization, modular exponentiation. These receive compact coverage.

**Omitted unless later justified:** flows, advanced matching, segment trees, heavy-light decomposition, suffix arrays, computational-geometry frameworks, FFT/NTT, advanced number theory, and extensive tree DP. Catalan topology counting is not evidence for a generic tree-DP chapter. Bellman-Ford receives an applicability warning/decision-table mention, not a full implementation: none of these weighted-path tasks supplies negative weights. Fenwick trees are an optional alternative to merge-sort inversions, not an extra chapter. KMP is justified as an efficient overlap-finding option, with simple direct search retained for small inputs.
