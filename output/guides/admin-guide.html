1. About this guide

This guide tells an administrator what the application offers, what each role may do, and the order in which to set the hospital up. Daily instructions for each job are in the separate Role Guides; how departments work together is in the Overall System Guide.

2. Application overview

REDMARS HMIS is a web application for one hospital. The left menu is grouped as Main, Clinical and Administration, and every user sees only what their role allows VERIFIED – SCREEN. The top bar shows who is signed in, the language (English, Dari, Pashto), a Change password link and Sign out.

What the administrator sees

The testing administrator's menu contained 24 workspaces VERIFIED – SCREEN:

GroupWorkspaces
MainCRM, Dashboard
ClinicalReception operations, Queue, Appointments, Patients, Follow-ups, Diagnosis codes, Interactions, Lab
AdministrationHuman resources, Finance & accounting, Invoices, Collections, Till, Users, Settings, Modules, Departments, Practitioners, Services, Lab tests, Lab panels, Drugs, Reports

The administrator does not see the Reception (check-in) screen, My consultations, Pharmacy, or any clinical writing function: those belong to the receptionist, doctor and pharmacist.

The administrator is a configurator and supervisor, not a clinician Under rule R2 an administrator can read clinical data (every read is recorded) but can never write it, and can never read psychiatric clinical notes. Patient registration, check-in and payment are receptionist functions. VERIFIED – CODE

Missing or insufficient permissions GAP

  • No role for lab supervisor, chief physician, nursing manager or department head; the matrix itself flags the lab-supervisor question.
  • No emergency “break-glass” access.
  • No separate cashier role: the receptionist is the cashier.
  • Nobody holds patient.delete, deliberately. Patients cannot be deleted; errors are marked “entered in error”.
  • Admin cannot do clinical work and cannot read psychiatric notes. An administrator who also needs to treat patients needs a separate doctor account.
  • HR approval (leave, roster, employee changes) sits only with the Administrator role. There is no manager-level approval for a department head.

6. Setup steps in detail

Step 1 — Secure the administrator account

  1. Click Change password in the top bar.
  2. Set a strong password known only to you. Never write it in documents.

Why: the administrator can see everything non-clinical. Required: current and new password.

Step 2 — Modules

Administration → Modules lists Outpatient (always on), Laboratory, Pharmacy, Inpatient (IPD), Emergency, Radiology, Billing, Reports, Finance & accounting, CRM and Human resources, each with an on/off switch VERIFIED – SCREEN. Turn off what the hospital will not use: the related menu items disappear and the server refuses those functions.

Depends on this: Lab menu and lab catalogue (Laboratory), Finance, CRM and HR workspaces.

Step 3 — Discount ceiling

Administration → Settings → “Maximum discount without approval (%)”, then Save VERIFIED – SCREEN. Receptionists and pharmacists may discount up to this percentage themselves; above it an administrator must approve at the till. The design default is 10%. Depends on this: every till discount.

Step 4 — Departments

  1. Open Administration → Departments.
  2. Under “Add a department” enter Code (for example OPD), choose Type (Outpatient, Inpatient, Emergency, Laboratory, Radiology, Pharmacy, Administration), enter Name, and optionally the Dari and Pashto names.
  3. Click Add department.

EXECUTED Five departments were added this way (OPD Outpatient, IPD Inpatient, EMR Emergency, LAB Laboratory, PHM Pharmacy). Wait for the new row to appear before adding the next one: when two departments were submitted about one second apart, two of the four were not saved. Each department row also has a Show rooms control for the rooms in that unit.

Departments can be deactivated, not deleted VERIFIED – SCREEN. Why: they are required by services, employees, practitioners, queues, reports, roster coverage and IPD beds. Check spelling: the test instance's only department is spelled “Information Technlogy”, and names cannot be edited on screen (only activated or deactivated).

Step 5–6 — HR calendar, positions, leave types, shifts

All under Human resources → Settings VERIFIED – SCREEN.

Blocker found on the testing instance The Positions, Leave types and Shift types forms on this tab did not save when tried several ways (typed values, ticking Clinical, filling the Dari and Pashto titles, pressing Enter, reloading to check). No error message appeared and the lists stayed empty. The Weekly rest days / Save controls form and Minimum shift coverage were not tested. The cause was found afterwards in the source code: the buttons on these forms were not set to submit (a fault shared by 28 buttons across HR, Reception operations, Finance, Appointments and Users). The fix has been made in the development copy and works there, but it has not yet been deployed to the testing server, so on the testing server this blocker remains until the new version is installed. See the development-team document, item D-01.

The HR Employees tab itself warns: “Create an active clinical position such as Doctor or Psychiatrist before adding the employee.” Public holidays are supported by the application's HR interface in the source code, but no holiday entry form was visible on the Settings tab on the testing instance. GAP Confirm where holidays are entered.

Step 7 — Specialities

Administration → Practitioners → Specialities: Code, Name, Add speciality EXECUTED (“PSY Psychiatry” saved and appeared in the speciality list and drop-down). Optional; used when describing practitioners (for example Psychiatry, Addiction medicine).

Step 8 — Services and fees

  1. Open Administration → Services.
  2. Choose the Department, enter Code, Name and Fee (AFN), click Add service.

EXECUTED Added “CONS-PSY Psychiatric Consultation, 500 AFN” and “CONS-FU Follow-up Consultation, 300 AFN” under the Outpatient Department; both appeared in the list as Active. These are test values, not real hospital prices.

Why: check-in builds the patient's bill from a service; without a service the receptionist cannot bill the visit VERIFIED – CODE. Create at least one consultation service per department that sees patients. Only administrators can change prices.

Step 9 — Drug formulary

Administration → Drugs VERIFIED – SCREEN:

  • Add a drug: Code and Generic name are required; Brand name, ATC code, Strength, Form optional. Optional prescribing defaults (route, frequency, duration) pre-fill a prescription. Sell price is the price per unit at dispense; blank means free-issue. Tick Controlled substance where applicable.
  • Import from CSV: paste rows under the header code,genericName,brandName,strength,form,isControlled,sellPrice; re-importing a code updates it.

EXECUTED A pasted CSV of ten test drugs (for example Sertraline, Risperidone, Diazepam as controlled) gave “Imported 10, skipped 0” and all ten appeared in the Formulary list. The import is the quickest way to load a real formulary.

Depends on this: prescribing, the interaction checker, pharmacy billing. Pharmacists may propose changes; the administrator approves (R9) VERIFIED – CODE.

Step 10 — Lab tests and panels

Administration → Lab tests: fields Code, Name, Name (Dari), Name (Pashto), Specimen, Unit, LOINC code, Price (AFN), then Add test VERIFIED – SCREEN. EXECUTED “CBC Complete Blood Count, blood, 150” and “GLU Blood Glucose (Random), blood, mg/dL, 80” were added and listed as Active. Lab panels (grouped tests) and per-test reference ranges were not tried. Depends on this: doctors can only order tests that exist here.

Step 11 — Employees

  1. Open Human resources → Employees.
  2. Under “New employee” enter first name, father name, last name, sex, phone, Department, Position, employment type (Permanent, Fixed term, Part time, Temporary, Volunteer), joined date (Shamsi) and base salary (AFN).
  3. Click Create employee. An employee number is issued automatically.

Employees are never deleted; leaving staff are marked exit, which disables the login and ends active sessions. Base salary is hidden from users without salary permission VERIFIED – CODE. The hospital's team recorded 24 real employees to import; no real data was imported into the testing instance.

Step 12 — Logins for clinical staff

Doctor, nurse, lab technician and pharmacist accounts cannot be made from Users: the application refuses clinical roles there and tells you to create the account from the employee record VERIFIED – CODE. On the employee record use Create account and enter username, optional email, a temporary password (at least 8 characters) and the roles. For a Doctor the employee must hold a clinical position; the practitioner profile and department link are created automatically.

The screen path for the account button inside the employee detail could not be confirmed live because no employee existed. GAP

EXECUTED The legacy route below was used to create one test practitioner “DR-001 Test Psychiatrist” (Psychiatry, no login). It saved and showed as Active, but its Departments column showed “None” although the Outpatient Department box had been ticked. Check this when you rehearse; reported to the development team.

Legacy route: Administration → Practitioners → Add a practitioner creates a practitioner profile with code, speciality, names, licence number, phone, login account (existing user) and departments. The screen advises using the HR record instead.

Step 13 — Logins for non-clinical staff

Administration → Users → Create a user VERIFIED – SCREEN: Username, Full name, Password, tick Roles (Auditor, Payroll officer, Accountant, Finance manager, Administrator, Receptionist, Management, Call center), Create user. The temporary password must be at least 8 characters and the user must change it at first sign-in.

The Staff accounts table shows username, full name, roles and status with Issue temporary password and Deactivate per row. Accounts are deactivated, never deleted.

Step 14 — Beds and reception

Reception operations → Desk & IPD → Add bed needs an inpatient department; the Bed board starts empty. Beds have status Available, Maintenance, Cleaning. Other tabs: Patient services, Shift control, Downtime VERIFIED – SCREEN.

Step 15 — CRM

CRM has tabs Leads, Contacts and family, Calls, Tasks & follow-ups, Appointments, and Workspace settings VERIFIED – SCREEN. Only the administrator can change workspace settings (crm.configure).

Step 16–17 — Finance

  1. Open Finance & accounting. Before initialisation only a Shamsi↔Gregorian date converter and the “Initialize the hospital books” form appear VERIFIED – SCREEN.
  2. Enter the start date (Shamsi) and click Create AFN chart of accounts. This creates the chart and the Shamsi fiscal years. The start date cannot be changed afterwards.
  3. Agree the start date and approved opening balances with the hospital's accountant first.
  4. Then configure payroll (finance manager or administrator), revenue mappings, panels and suppliers as needed.
Do not initialise on production without the accountant The start date is permanent, and the project's own assessment records that unpaid invoices from before go-live cannot yet be loaded individually and that the accountant and cutover date were still pending. VERIFIED – CODE

10. Operational recommendations RECOMMENDATION

  1. Rehearse first. Run one full patient journey on the testing instance (check-in, queue, consultation, lab, pharmacy, till) before any real patient.
  2. Keep real hospital data separate from test data. Use a clean database for go-live; never reuse the testing instance.
  3. Name things carefully. Departments and services cannot be renamed on screen.
  4. Review audit weekly. Reports → Audit log and Errors.
  5. Review Collections and Till daily with the receptionist supervisor.
  6. Review credentials monthly. The application can compute expiry status but no automatic daily reminder runs.
  7. Back up. The project provides database backup commands (db:backup, db:restore) and a testing-server guide; schedule them with the IT team.
  8. Keep passwords out of documents and force change on first sign-in (already enforced for temporary passwords).
  9. Confirm with the hospital the open decisions in Section 11 before go-live.
