1. How to read this document

Each item has an ID, a severity, what was seen, how it was seen, and a suggested action. Nothing here has been fixed. Items were found by (a) using the screens of the testing instance as the testing administrator and (b) reading the source code. They are not a full security audit or full test.

SeverityMeaning
BLOCKERStops a required set-up or daily task. Fix before go-live.
HIGHLikely to cause wrong data, confusion or a safety/finance risk.
MEDIUMInconsistency or gap with a workaround.
LOW / QUESTIONPolish, wording, or a question for the hospital or the team.
Evidence labelMeaning
SEENObserved on the testing instance.
CODERead in the source code; not reproduced live.
UNCONFIRMEDSuspicion only; needs the team to check.

2. Defects seen on the testing instance

IDSeverityFindingSuggested action
D-01BLOCKER
ROOT CAUSE FOUND · FIXED LOCALLY		 HR settings “Add” forms saved nothing and showed no error. At Human resources → Settings, Add position, Add leave type and Add shift did nothing on the testing instance. SEEN
Root cause: the shared Button (apps/web/src/components/ui/button.tsx) is built on the Base UI library, which gives every button type="button" unless told otherwise. Many forms use a bare <Button> and so never submit. Confirmed on the local build: before the fix the button type was “button” and no request was sent; after adding type="submit" the form sent POST /hr/positions and POST /hr/leave-types and both returned 201. The API itself was fine (a direct call also returned 201). CODE SEEN
Impact: no positions, so no employees, no clinical logins, no leave or roster.
Scope: an automated scan of every form found 28 affected buttons in 6 files: HrPage (11), ReceptionOperationsPage (11: submit request, waitlist, add bed, contact consent, document upload, coverage, deposit, reminder, handover, close till, downtime marker), FinancePayables (2), FinanceStatements (2), AppointmentsPage (1: save rescheduled appointment), UsersPage (1: create account).		 Done in the working tree (not committed or deployed): added type="submit" to the 28 buttons; web typecheck and build pass. Still to do: redeploy to the testing server and re-test; add a guard so this cannot return (D-26).
D-02HIGH The HR settings forms swallow errors. In apps/web/src/pages/HrPage.tsx the add mutation (about line 1169) and saveConfig mutation have only onSuccess; there is no onError or visible error state. Any server rejection (validation, permission, duplicate) looks like “nothing happened”. CODE
Impact: this is not the cause of D-01, but it would hide any future server rejection (validation, permission, duplicate).		 Show the server's error message on every mutation. Check other pages for the same pattern.
D-03WITHDRAWN Practitioner saved with “Departments: None”. Seen on the testing server after ticking a department box through the browser-automation tool. On the local build the same tool failed in the same way on the Users form (“Assign at least one role”) until the boxes were clicked with a real mouse event, after which the form worked. This was a testing-tool artefact, not an application fault, and is withdrawn. SEEN None. Re-check by hand on the testing server if wanted.
D-04HIGH Clinical-staff login path is only reachable through HR, which is blocked by D-01. The generic Users form offers only Auditor, Payroll officer, Accountant, Finance manager, Administrator, Receptionist, Management, Call center. Doctor, nurse, lab technician and pharmacist accounts must come from an employee record (the Users service rejects clinical roles with a message). SEEN CODE
Impact: while D-01 was open, a hospital could not create any clinical user.		 Fix D-01. Consider a clear message on the Users form explaining where clinical accounts are created (a short note exists only in the Doctor access panel).
D-05HIGH Finance cutover blocker (already known to the project). Unpaid invoices from before go-live cannot be loaded individually; a general opening journal can balance while the AR comparison differs, and period close refuses it. Accountant/approver and cutover date still pending. CODE (docs/finance-roadmap-assessment.md) Build the controlled legacy-receivable migration and receipt workflow before production cutover.
D-06HIGH HR employee and attendance data do not reach payroll. Finance payroll employees are separate from HR employees; the link is still an open task and payroll uses manually adjusted attendance. CODE (docs/hr-roadmap-assessment.md)
Impact: duplicate data entry and risk of salary mismatch.		 Decide whether HR becomes the payroll master (hospital decision), then add the explicit link.
D-07HIGH Shared testing credentials. The testing administrator password was passed in plain text in chat and is a simple pattern. SEEN
Impact: if the same instance later holds real data, the account is weak and already shared.		 Rotate the password and use a unique one per environment. Do not put real patient data on this instance.

3. Gaps and inconsistencies

IDSeverityFindingSuggested action
D-08MEDIUM Two of four departments not saved when submitted one second apart. Adding IPD, EMR, LAB and PHM with about 1 s between submits saved IPD and LAB only; EMR and PHM were missing, then saved when retried with 3 s gaps. SEEN May be an automation timing effect; the form gave no feedback either way. Check for a double-submit or stale-state problem; show success/failure feedback.
D-09MEDIUM Departments cannot be renamed or edited, only deactivated. The testing instance's first department is misspelled (“Information Technlogy”) and cannot be corrected on screen. SEEN Add edit for name, local names and type, or document the workaround.
D-10MEDIUM No screen to create or edit roles and permissions. There are 12 fixed roles; no route for role management exists in the API. CODE Also no roles for lab supervisor, chief physician, nursing manager or department head, and no emergency “break-glass” access. Decide if roles must be configurable; otherwise document that role changes are a software change. Design the missing roles with the hospital (the permission matrix already lists lab supervisor and break-glass as open questions).
D-11MEDIUM Screens not found for three administrator tasks. (a) Entering public holidays (API exists, no form on the HR Settings tab); (b) changing the roles of an existing user (role.assign exists, no control on the Users list); (c) listing user accounts with no employee record (an “orphans” API route exists). SEEN CODE Confirm where each lives; add screens if missing.
D-12MEDIUM Credential-expiry reminders have a runner but no scheduler. The HR assessment states the daily invocation is not wired. CODE Attach the runner to a scheduled job or add a visible “run now” with a last-run time.
D-13MEDIUM Lab sample collection grant for nurses is probably a typo. lab.collect_sample gives the nurse rule R9 (“propose catalogue changes”), which does not fit collecting a sample; the source comment says likely R8. CODE (apps/api/src/auth/permissions.ts) Confirm the intended rule with the hospital and correct the matrix.
D-14MEDIUM Same technician can enter and verify a lab result. Flagged as open question 1 in the matrix. In a psychiatric hospital drug-level and safety tests deserve a second check. CODE Hospital decision; add a lab supervisor role or a “verifier must differ” rule if wanted.
D-15MEDIUM Check-in requires payment at once. The reception check-in route requires invoice.create and payment.receive and registers, queues, bills and takes payment in one save. No “bill later”, insurance-pending or emergency-no-payment path was seen on the check-in design. CODE Emergency arrivals exist under Reception operations, but how an unpaid emergency patient is handled was not tested. Confirm the intended policy for emergency and insured patients; document or extend.
D-16MEDIUM Modules switched on that have no visible screens. Radiology, Emergency and Inpatient (IPD) are On in Modules, but the menu has no radiology or ward-round screens; IPD and emergency appear only as Reception-operations functions (beds, admission requests, emergency arrival). SEEN Say clearly in the Modules page which functions each switch controls, or hide modules that are not built.

D-33LOWLocal seed differs from the testing server. The local seed creates 19 departments and names the facility “…Specialty Hospital”; the testing server shows “…Treatment Hospital”. D-34MEDIUMReceipts carry another hospital's contact details. The printed bill and receipt show “Kolola Pushta Bus Stop, Kabul” and an email for “farhathsp”, while the heading reads Axon Nura. There is a migration that renamed the Farhat facility to Axon, so the footer text was probably left behind in print settings. SEEN (local build, receipt INV-2026-0007)Move the receipt address, phone and email into facility settings and set the correct Axon values.
D-35MEDIUMA zero-price lab order shows two different payment states. The doctor ordered a panel priced 0.00. Collections lists it as “Unpaid 0.00 AFN” and the bill page says “NOTHING TO PAY” with no way to settle it, while the Lab screen shows the same order as “Paid” and lets the sample be collected. SEENTreat a zero bill as settled everywhere, or block ordering tests that have no price.
D-36MEDIUMSeed catalogue quality. The local database holds 360 services with many at 0.00, several duplicate “OPD” entries, and entries named after people (for example a doctor's name) listed as services; 1,297 drugs, many with no price. At check-in a zero-price service can be sold for free. Pharmacy staff had to type a unit price for the drug before billing. SEENClean the catalogue before go-live; consider requiring a price (or an explicit “free” flag) for every billable item.
D-37LOWQuantity box pre-fills, then appends. On the prescription sheet the Qty box was filled automatically with 30; typing 30 into it produced 3030. A mistake like that would bill 100 times too many tablets. SEENSelect the box content on focus, or show the calculated quantity as a placeholder.
D-38LOWAccount creation lists differ. Users → Create a user offers Auditor, Payroll officer, Accountant, Finance manager, Administrator, Receptionist, Management, Call center. HR employee → Create system account offers Doctor, Nurse, Lab technician, Pharmacist, Receptionist, Payroll officer, Accountant. There is no screen path for linking Administrator, Management, Auditor, Finance manager or Call center accounts to an employee record. SEENDecide whether every account should be tied to an employee, and align the two lists.
D-39MEDIUMCall center sees a 3-day recall window; receptionist sees 30 days. The follow-up that the doctor set for 7 days ahead did not appear for the call-center user until the date range was changed by hand (the “Later window” button jumps a whole month). The call center's whole job is this list. SEENUse the same default window for every role, or let the call center choose “next 30 days”.
D-40MEDIUMCRM call workflows are blocked until an administrator confirms an escalation contact. The CRM Tasks and Workspace pages say “An administrator must confirm the staffed escalation contact before call workflows begin”, and service areas and safe-contact instructions show “Not configured”. This setup step is not mentioned anywhere else. SEENAdd it to the setup checklist and the Administrator Guide; consider a banner on the admin dashboard.
D-41LOWSettings forms keep their values after saving. After adding a shift type on HR → Settings the code, name and times stayed in the form, so a second click would try to add a duplicate. SEENClear the form on success.
D-42LOWDate fields are pre-filled and appended to. The roster From/To boxes were pre-filled, and typing into them produced “1405-08-101405-08-10”; no error was shown and the roster stayed empty until the text was replaced. SEENSelect the content on focus, or validate and show a message.
D-43LOWAppointments are booked from the patient record, not from the Appointments page. The Appointments page has no “New appointment” control; booking (“Book a follow-up”, a date, not a time) is on the patient record. First-time users may not find it. SEENAdd a “Book” link on the Appointments page.
D-44LOWPossible confusion between “Cancelled” and “Rescheduled”. Rescheduling keeps the old booking marked Cancelled with the note “Rescheduled to …” and adds a new Booked row. That matches the design (history is kept) but will inflate cancellation counts in reports unless they exclude rescheduled rows. SEENCheck the no-show/cancellation counts in Reports.
